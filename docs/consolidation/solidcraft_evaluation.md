# SolidCraft consolidation evaluation — 2026-10-14

## Decision

**Proceed with a thin, transactional SolidCraft integration experiment; do not
switch the production default yet.** Freeze new cadgen modeling recipes. Preserve
the current OCCT plate and Fusion paths as references, not competing expansion
tracks. SolidCraft has demonstrated enough native modeling and editing to make
rebuilding its solver, feature history and document system unnecessary for this
product slice. Two fixtures do not establish general kernel superiority.

ParamAItric should own measured requirements, supported recipe selection, input
and fit validation, transaction sequencing, independent verification and acceptance.
SolidCraft should own sketches, feature evaluation/editing, native documents and
exports; its existing UI is the candidate review/editing experience. OCCT can
remain an independent STEP verifier without becoming a second product modeler.

This is a conditional architecture decision based on the bounded proof below.
Interactive UI/target-hardware qualification and the integration safety gates
remain separate; a successful export or tool reply is insufficient.

## Real geometry and native editing

Fixed evaluation command scripts use SolidCraft's public API. They are test inputs,
not new cadgen production recipes. Every solid mutation is followed by feature
health inspection and a fresh-process OCCT read of exported STEP before the next
mutation. STEP dimensions/placement use 0.01 mm absolute tolerance; analytic
volume uses max(0.01 mm³, 1e-6 relative). Binary STL checks require finite values,
valid length/count, matching envelope and signed volume within 0.1%. Full mesh
manifold/self-intersection checks and structural certification are not claimed.

| Proof | Demonstrated |
|---|---|
| Plate | 80×60×5 mm, one valid solid, 10 mm through-bore at (40,30); analytic volume and placement checked independently |
| Plate edit | Width 100 mm; bore at (50,30), same diameter; true sketch expressions `width/2`, `height/2` |
| Native editability | Save `.solidcraft`, close process, reopen in a new process, inspect authored parameters/timeline, edit and re-export; no STEP import used as editability evidence |
| Repeated regeneration | Alternate original/edited width five times per family, then cold-reopen edited native document and verify again |
| L-profile | Existing fixture: flat XY L, 50×80×5 mm, 5 mm legs; 3125 mm³; actual reentrant corner, material in both legs and missing interior checked |
| L edits | Width 70 mm gives 3625 mm³; a leg edit to 6 mm changes both legs and the verified volume |
| Specific fillet | Radius 1.5 mm on the outer vertical edge at (70,0,2.5); cylinder location/radius and analytic volume delta checked; native reopen and width edit to 90 mm preserve it |

The L is not a folded angle bracket and this fixture contains no mounting holes.
No claim is made about arbitrary fillets, additional families or structural use.
CPU snapshots of the plate, L and filleted L were generated by SolidCraft and
visually reviewed. Screenshots are diagnostics, not geometric proof.

The optional official web UI bundle download timed out after a partial transfer;
one bounded resume failed when the host network became unreachable. The partial
file was renamed `.partial`, never passed checksum verification and was not
extracted or executed. Interactive SolidCraft UI, desktop app interaction and
Strix Halo GPU/browser qualification therefore remain **not_run**. The verified
native CLI and CPU renders are distinct evidence; no custom UI was built.

## Failure and cancellation findings

| Experiment | Observed behavior | Product consequence |
|---|---|---|
| Width = 0 | `isError: false`, but nonempty feature `errors`; authored state changed to the invalid parameter | Validate dimensions before submission; inspect `errors` and every timeline feature; never accept from `isError` alone |
| Oversized fillet | Explicit tool error, authored state unchanged | Safe refusal in this case; retain required geometry read-back |
| Missing body/edge and parameter reference | Explicit errors, authored state unchanged | Preserve structured failure and require explicit recovery |
| Far coordinate edge pick | Binary rejected the pick and reported nearest-edge distance | Better than the pinned modeling guide's unbounded-nearest-pick warning; use tested binary behavior, not that stale guidance |
| Batch fails after parameter change | Explicit failure/index; native checkpoint rolled back the prior change/history | Reuse native checkpoints and verify restored geometry |
| Explicit checkpoint recovery | Restored parameter/timeline/undo state and independently verified geometry after every negative test | Recovery is demonstrated for these cases, not arbitrary history |
| MCP cancellation notification | Batch continued all 601 steps and wrote its final native file **after** cancellation was sent | Native protocol cancellation is insufficient for ParamAItric acceptance |
| Kill isolated process group | Process stopped, no post-cancel sentinel file, source native hash unchanged | A disposable worker and application-owned atomic acceptance can supply the required boundary; integration remains to be implemented/tested |

The cancellation test sends a real `notifications/cancelled` for the active MCP
request. File mtime is compared with send time, rather than assuming a delayed
response proves continued execution. The process-termination test is distinct;
it does not turn missing native cancellation into a pass. Prior files remain
immutable, and scratch outputs are not accepted revisions.

SolidCraft's internal measured plate volume was approximately 23607.3661 mm³;
independent OCCT read-back was 23607.3009183 mm³, matching the analytic value.
That small native measurement difference exceeds this recipe's 1e-6 audit
tolerance. Treat native measures as provenance-labelled diagnostics unless their
accuracy is qualified; retain the independent required gate.

## What to reuse and stop building

| Responsibility | Direction |
|---|---|
| Kernel, sketches/solver, timeline and feature editor | Reuse SolidCraft; do not rebuild in ParamAItric |
| Native parameterized document | Reuse `.solidcraft`; verify reopen/edit/regeneration and hash it with outputs |
| Viewer and interactive CAD controls | Evaluate/reuse SolidCraft UI; no custom frontend or renderer |
| STEP/STL exporter | Reuse SolidCraft; verify saved artifacts independently |
| Requirements, missing fit dimensions, units and approved recipes | Keep ParamAItric's curated product contract; reuse upstream guidance only where reliable |
| Acceptance, cancellation, rollback and provenance | Keep application ownership; use native checkpoints plus isolated workers and atomic publication |
| Modeling reference | Freeze existing cadgen/OCCT plate; Fusion remains default/reference until the opt-in path earns acceptance |

Upstream modeling/editing/checking guides already cover substantial CAD-agent
workflow. They can inform command plans and future upstream contributions, but
their own measure/screenshot heuristics do not replace ParamAItric's verification
policy. No upstream issue or message was posted during this experiment.

## Reproduce

```bash
python3 scripts/prepare_solidcraft_resources.py
python3 scripts/prepare_solidcraft_resources.py --verify-only
# Optional, when network/browser UI qualification is available:
python3 scripts/prepare_solidcraft_resources.py --include-web
.venv/bin/python -m evaluations.solidcraft_eval \
  --solidcraft-cli "$PWD/.external-resources/solidcraft/v0.11.1/solidcraft-0.11.1-linux-x86_64/bin/solidcraft-cli" \
  --cad-python "$PWD/.external-resources/cad-env/bin/python" \
  --output-root "$PWD/manual_test_output/solidcraft-evaluation"
```

Provision the MCP/test venv and pinned CAD reader from the existing integration
runbook if needed. Each experiment gets a new output folder. XDG state/recovery
and scratch paths are scoped there; native MCP file access is restricted to the
explicit experiment directories. Process/resource bounds do not constitute an
OS sandbox. The runner reports observed failures; completing it is not a green
engine-adoption gate.

Upstream reference totals are versioned claims, not our results. The fetched live
README said 75/76; the release-pinned `docs/oracle.md` says 82/82. We did not rerun
the whole upstream oracle suite. The pinned robustness report includes substantial
failures/timeouts on random designs and warns that its comparison predates later
guard changes. Neither figure establishes general superiority over OCCT.

## Exact next task

Implement a small opt-in SolidCraft execution bridge for these two fixed part
families behind ParamAItric's existing guided surface. Reuse existing acceptance,
integrity and input-validation code where practical. Required before promotion:
disposable process-group cancellation, immutable staged native/export artifacts,
atomic acceptance, timeline/parameter error detection even with `isError: false`,
checkpoint recovery and fresh independent STEP verification. Add the demonstrated
cancellation case as a regression. Do not expand cadgen recipes or kernels.

After that gate, qualify native/interactive review on the target hardware and
decide whether to make SolidCraft primary and retire redundant planned modeling
work. Keep Fusion and the frozen OCCT reference until that decision has evidence.
